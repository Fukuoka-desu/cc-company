# 秘書との日常

セットアップ後は、`/company` で秘書に話しかけるだけです。

## TODO管理

```
> /company
秘書: おはようございます！何かありますか？

> 今日やること教えて
秘書: 今日のTODOです:
  - [ ] クライアントAへ見積もり送付
  - [ ] LP設計書のレビュー

> 「Stripe決済の実装」を追加して、優先度高で
秘書: 追加しました！
  - [ ] Stripe決済の実装 | 優先度: 高
```

TODOは `secretary/todos/YYYY-MM-DD.md` に保存されます。

## 壁打ち・相談

```
> ちょっと壁打ちしたいんだけど、料金体系で悩んでて
秘書: いいですね！聞かせてください。
      今考えている選択肢はありますか？

> 月額制かBuyout（買い切り）か迷ってる
秘書: それぞれのメリットを整理してみましょう...
      ...
      結論をメモに保存しておきましょうか？
```

壁打ちの結果は `secretary/notes/` に保存されます。

## クイックメモ

```
> あ、さっき思いついたんだけど、LPにFAQセクション追加したい
秘書: メモしておきますね！
  → secretary/inbox/2026-03-16.md に記録
```

思いつきやアイデアは `secretary/inbox/` にキャプチャされます。

## 判断に迷う依頼

```
> この件、どこに入れるのがいいかまだ分からない
秘書: いったん inbox に入れておきますね。
      後で整理しやすいように要点も添えておきます。
  → secretary/inbox/2026-03-21.md に記録
```

v3 では、秘書が迷った内容を無理に `notes/` や既存部署へ振り分けません。まず `inbox` に保留するのが標準動作です。

## 部署がまだない仕事

```
> 競合サービスを3社調べて比較して
秘書: リサーチ系の依頼ですね。
      まだリサーチ部門がないので、まずは inbox に整理しておきます。
      必要ならリサーチ部門も提案しますね。
```

専門作業なのに対象部署が未作成なら、秘書は `secretary/inbox/YYYY-MM-DD.md` に依頼要約を保存し、`.company/state.json` の提案カウンタを更新します。

## 自動記録

秘書は以下を言われなくても自動で記録します：

| 内容 | 保存先 |
|------|--------|
| 意思決定 | `secretary/notes/YYYY-MM-DD-decisions.md` |
| 学び・気づき | `secretary/notes/YYYY-MM-DD-learnings.md` |
| アイデア | `secretary/inbox/YYYY-MM-DD.md` |

## 保存ルールの優先順位

- TODOや日次メモは `YYYY-MM-DD.md` に追記
- 壁打ちや相談の結論は `notes/<topic>.md` に保存
- 専門作業で部署がまだなければ `inbox` に保留
- 分類不能な内容も `inbox` を優先
