# v3 への移行

既存の v1 / v2 組織を v3 の安定ルーティング仕様へ揃えるための移行手順です。

## 自動検出

`/company` を実行すると、以下を自動検出して v3 への移行を提案します。

- `.company/ceo/` がある legacy 構成
- `.company/` はあるが `.company/state.json` がない v2 構成

```
> /company

秘書: 既存の組織を検出しました。v3 に移行しましょうか？

      変更点:
      - 入力分類 → intent ベースに統一
      - 迷った入力 → secretary/inbox/ に統一
      - state.json → 提案状態を永続化
      - legacy の CEO / reviews → 整理対象
      - 使用中の部署 → そのまま引き継ぎ

      アップグレードしてよいですか？
```

## 何が変わるか

| 旧構成 | v3 |
|----|-----|
| 迷った入力の扱いがあいまい | `secretary/inbox/` に統一 |
| 部署提案が会話依存 | `state.json` で永続化 |
| legacy の CEO / reviews が残ることがある | 必要に応じて整理 |
| ルーティング基準が説明中心 | intent ベースの仕様に統一 |

## 移行時の処理

1. 既存のオーナー情報と使用中の部署を引き継ぐ
2. `.company/state.json` を生成または更新する
3. `ceo/` と `reviews/` があれば整理する
4. `.company/CLAUDE.md` を v3 ルールで再生成する
5. `secretary/CLAUDE.md` を v3 版に更新する
6. 今後の部署提案は `state.json` ベースで行う

::: warning 注意
使用中の部署や実データは削除しません。移行はルーティングルールと状態管理の追加が中心です。
:::

## アップグレードしない場合

拒否した場合は現在の構成のまま運用を続けられます。次回 `/company` 実行時に再度提案されます。
