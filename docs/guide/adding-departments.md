# 部署を追加する

cc-company の核心機能です。v3 では、秘書は感覚ではなく `.company/state.json` の記録を根拠に部署追加を提案します。

## 秘書からの提案

同じ領域の専門作業が繰り返されると、秘書が提案してきます。

```
> 競合サービスについて調べて
秘書: リサーチ系の依頼として inbox に整理しておきますね。
  → secretary/inbox/2026-03-21.md に保存

（同様の依頼がもう一度あると...）

> 海外のトレンドも調べたい
秘書: リサーチ系の依頼が続いています。
      `.company/state.json` でも提案ラインに達したので、
      リサーチ部門を作ると topics/ で整理できます。作りましょうか？

あなた: 作って

→ research/ が自動生成される
```

::: tip ポイント
部署がまだない場合、秘書はまず `secretary/inbox/` に依頼要約を保存します。誤った部署や `notes/` に無理に振り分けないのが v3 の方針です。
:::

## 自分から依頼する

もちろん、直接依頼もできます。

```
> PM部門を作って
秘書: PM部門を作成しますね！

→ pm/ が自動生成される
```

明示的な作成依頼がある場合は、提案カウンタを待たずに即時作成します。

## 追加される部署の構成

部署が追加されると、以下が自動生成されます：

- **部署フォルダ** — `.company/[department]/`
- **部署の CLAUDE.md** — その部署のルールと振る舞い
- **サブフォルダ** — 部署ごとのファイル管理用
- **テンプレート** — ファイル作成時の雛形
- **state.json 更新** — 部署一覧と提案状態の更新

例えば、リサーチ部門を追加すると：

```
.company/
├── CLAUDE.md              ← 部署一覧が更新される
├── secretary/
└── research/              ← 新しく追加
    ├── CLAUDE.md           ← リサーチのルール
    └── topics/             ← 調査トピック管理
```

## 利用可能な部署

| 部署 | 担当領域 |
|------|---------|
| PM | プロジェクト進捗、チケット管理 |
| リサーチ | 市場調査、競合分析、技術調査 |
| マーケティング | コンテンツ企画、SNS、キャンペーン |
| 開発 | 技術ドキュメント、設計、デバッグ |
| 経理 | 請求書、経費、売上管理 |
| 営業 | クライアント管理、提案書 |
| クリエイティブ | デザインブリーフ、ブランド管理 |
| 人事 | 採用管理、チーム管理 |

詳細は [部署一覧リファレンス](/reference/departments) を参照してください。
